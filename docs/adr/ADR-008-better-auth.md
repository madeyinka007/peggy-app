# ADR-008 — Better Auth for Human AuthN (MVP)

**Status:** Accepted (spike verified 2026-10-25)
**Resolves:** OQ-01

## Context

Peggy needs human authentication (admin users) for the admin SPA. Decision was deferred to a spike (see `docs/00-better-auth-spike.md`). This ADR records the finalized strategy.

## Decision

Use Better Auth behind the `AuthPort` boundary. Verified against `better-auth@1.7.12` + `@better-auth/drizzle-adapter@1.7.12` + `drizzle-orm@0.45.4` + `zod@4.3.6`.

### Password hashing
- **MVP:** Better Auth default scrypt (Node native, OWASP-acceptable, zero deps).
- **Upgrade path (post-MVP):** custom Argon2id via `emailAndPassword.password.{hash, verify}` with `@node-rs/argon2` (memoryCost 65536, timeCost 3, parallelism 4, Argon2id). Dual-verify transition window, then retire scrypt.
- FR-024 updated: "passwords hashed with Better Auth scrypt default; Argon2id upgrade reserved."

### Session store
- Better Auth owns `user`, `session`, `account`, `verification` tables, generated by `@better-auth/cli generate --adapter drizzle`. Schema committed verbatim; Peggy extends via `additionalFields`, never hand-writes core tables.
- Peggy's `users` table IS Better Auth's `user` table, extended with `additionalFields`: `displayName`, `avatarAssetId`, `isActive`, `isSuperAdmin`.
- Peggy's `sessions` table IS Better Auth's `session` table + `revokedAt` (explicit logout tombstone).
- ID interop: `advanced.database.generateId = false` so Postgres generates IDs. `user.id` = `uuid` (Peggy UUIDv7), `session.id/account.id/verification.id` = `text` (BA internal), `userId` FKs = `uuid`.
- Expiry: `expiresIn` 7 days, `updateAge` 24h, `freshAge` 1 day. `cookieCache` enabled, 5-min maxAge, `jwe` strategy.

### Express mounting
- `app.all("/api/auth/*", toNodeHandler(auth))` BEFORE `express.json()`.
- CORS before auth handler. Express v5 wildcard `{*any}` if needed (not required in spike).

### Lambda compatibility
- Stateless handler + DB sessions + cookieCache. Verified under `serverless-http` with `AWS_LAMBDA_FUNCTION_NAME` set (required for setResponse drain logic).
- Neon HTTP driver interop: **verified locally with pooled PG**. Neon HTTP specifically (C-01) to be confirmed on a Neon branch before prod deploy; fallback is pooled `pg` for auth routes only.

### Multi-tenant
- Organization plugin NOT installed in MVP (D2 single-project). Adoption path recorded for future minor-version migration. No `tenant_id` columns in MVP.

## Spike verification results (C-01…C-05)
- C-01: ✅ sign-up/sign-in/session-read 200 on local PG (baseline text IDs + UUID interop both pass)
- C-02: ✅ `emailAndPassword.password.{hash,verify}` and `additionalFields` shapes compile
- C-03: ✅ toNodeHandler works under serverless-http (Lambda env vars required for setResponse drain)
- C-04: ✅ cookieCache JWE works (`better-auth.session_data` JWE cookie, Max-Age=300, HttpOnly, SameSite=Lax)
- C-05: ✅ 317 req/s, p50 140ms, p99 304ms, 0 errors, all 2xx

## Consequences
- All auth tables generated by CLI; Peggy migrations include CLI output verbatim.
- `packages/auth` wraps Better Auth behind `AuthPort`.
- `packages/db` schema includes both system tables and Better Auth tables.
- Rate limiting on auth routes is per-target (OQ-03), counters in Postgres.
